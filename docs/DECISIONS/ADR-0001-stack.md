# ADR-0001: Technology stack and bootstrap decisions

Status: Accepted
Date: 2026-11-15

Context: P0 must freeze contracts and stand up a runnable skeleton (PRD §15.3,
P0 card). The PRD fixes the product shape (§4–§8) but leaves implementation
choices open within the approved dependency set (§22.B).

Decision:

1. **Monorepo:** pnpm workspaces; packages `@kirana/{shared,db,server,web,e2e}`.
   `shared/**` is contract territory (AGENTS.md §4).
2. **Runtime:** Node.js 22 LTS. TypeScript `strict: true` everywhere, plus
   `noUncheckedIndexedAccess` (AGENTS.md §5 forbids non-null `!` on user data).
3. **Server:** Fastify 5 + `@fastify/cookie` + `@fastify/static` + `@fastify/sensible`,
   `pino` logging. `@fastify/rate-limit` deferred to P4 (needs sessions to have
   something to rate-limit against); `fastify-type-provider-zod` deferred to P1
   when the first real endpoint lands — P0 has no zod-validated routes, and we
   verify zod-version compatibility then instead of guessing now.
4. **Database:** SQLite via `better-sqlite3` (sync, single writer) + `drizzle-orm`
   for typed queries. **Migrations are hand-written SQL files** applied by a
   ~60-line runner in `db/migrate.ts`, tracked in a `__migrations` table — the
   DDL in PRD §5.2 is the source of truth, so `drizzle-kit` (generate-SQL-from-
   schema tooling) is deferred until a workflow actually needs it. A schema-hash
   test (G0.2) pins the migrated shape.
5. **Contracts:** Zod **v4** in `shared/contracts.ts`. `openapi.json` is generated
   with `z.toJSONSchema()` (built into zod v4) plus a small registry in
   `scripts/gen-openapi.ts` — avoids adding an OpenAPI-conversion dependency,
   which §22.B would otherwise require an ADR for.
6. **Web:** React 19 + Vite + `react-router` v7 + `@tanstack/react-query` v5 +
   Tailwind CSS 4 (`@tailwindcss/vite`), design tokens in `web/src/styles/tokens.css`
   mapped to Tailwind `@theme` (PRD §8.2). Deferred to their first-use phase:
   `vaul`/`@radix-ui/*` (P2 sheets), `fuse.js` (P2 search), `lucide-react` (P1 icons),
   `vite-plugin-pwa` (P4), `clsx`/`tailwind-merge` (P1).
7. **Tests:** Vitest (unit + integration, `db/__tests__`, `server/__tests__`,
   `shared/__tests__`), Playwright (E2E, mobile viewport 375×667).
8. **Timestamps/IDs:** UTC epoch ms integers (INV-10); UUIDv7 strings everywhere
   (§7.1) generated by a small `shared/ids.ts` using `crypto.randomUUID`-based
   v7 construction (no dependency).

Consequences: later phases are additive; any change to `shared/**`, the DDL, or
`openapi.json` needs a `contract:` PR + ADR. The schema-hash file
(`db/schema-hash.txt`) must be regenerated with every new migration.

Alternatives rejected:
- `drizzle-kit` migrations now: generates SQL from TS schema, inverting the PRD's
  "DDL is the deliverable" stance; adds a moving part with no P0 payoff.
- Zod v3: older, but v4 is stable, has built-in JSON-Schema export (needed for
  `openapi.json`), and the deferred type-provider can be compatibility-checked
  at P1 with no cost now.
- Turborepo/Nx: not in §22.B; `pnpm -r` topological ordering is sufficient at
  five packages.

Deviations recorded: commits land directly on `main` (one per task card,
Conventional Commits + `Refs:` trailers) until a remote exists; branch/PR
conventions apply from P1 or the first remote push (AGENTS.md §7 adapted).

Refs: PRD §4.2, §5.2, §5.5, §7.1, §8.2, §12.1, §15.3, §22.A, §22.B
